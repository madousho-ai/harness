# skill

系统提示词里列着这个工作区可用的 skill。**接到活、动手之前，先把那份列表过一遍**，问哪一条覆盖了你接下来要做的事。这是一个有时点的动作，做完再开工 —— 做到一半才想起来查，手法早就定了。

**之后每换一类动作再过一遍。** 一件事走下来会跨好几道边界，开头那一遍是按开头那件事问的，答不了三步之后的问题。

对上了就加载。写第一个失败测试之前加载 test-driven-development，做普通 commit 之外的 git 操作之前加载 git-master，要按语法结构搜代码之前加载 ast-grep。**这三个是举例，列表本身才是清单** —— 你手上的活未必长得像它们中的任何一个，照样可能在列表里有对应的那一条。

skill 装的是提示词放不下的流程细节，也是这个工作区自己的约定到达你的通道。提示词写「这个项目的东西长什么样」，skill 写「怎么操作」，两边都要。

skill 给的是通用做法，项目自己的文档给的是这一次必须做成什么样。两者冲突时照文档做，并说出你在哪儿偏离了 skill。
